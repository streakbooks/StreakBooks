# LinkBooks platform benchmark and bounded code audit — 31 October 2026

## Scope and evidence

This reviews the published capabilities of 15 accounting platforms and inspects LinkBooks' existing accounting, reporting, workflow, permission, integration and voice code. Sources below were consulted on the review date. This is **not** a hands-on trial, penetration test, vendor performance benchmark, legal compliance certification or verification of private vendor architecture. Features differ by country, edition, subscription and paid add-on. No unsupported numerical ranking or pricing comparison is implied. Vendor references to AI are observations, not dependencies added to LinkBooks.

The integration base includes the newer Action Center and customer/supplier portal source work from main; this voice change preserves it and adds the Portal inbox tab to the shared route catalog. Live notification/portal migration, delivery and payment-provider readiness are not certified by these voice tests.

Historical LinkBooks audit documents sometimes describe earlier implementations. Current code and tests take priority: for example, supplier statements now have a real route, despite an older feature matrix marking them missing. A route or passing unit test alone does not establish production deployment or live integration readiness.

## Implemented scope and outstanding programme

This delivery implements the Phase 15 wake system and the accompanying voice acceptance fixes, rather than adding speculative accounting tables, payment integrations or untested ledger automation. It also fixes the two concrete form-business-rule discrepancies found above. It does **not** establish that every button/API/integration in the entire application works or that all 15 products' advanced capabilities have been implemented.

Priorities for subsequent bounded releases are: production migration/RLS/reconciliation verification; external integration readiness; independently measured wake accuracy and browser/OS coverage; a documented country-specific tax/filing scope; transactional idempotency for draft creation; catalog-versus-deployment consistency; and workload/restore/monitoring evidence. Each needs an explicit implementation contract and regression evidence before being advertised. The detailed voice architecture, engine licensing/privacy assessment and verification boundaries are in [the Phase 15 engine decision](../voice-wake-engine-assessment.md) and [Signal user guide](../voice-commands.md).
