Turn the Superadmin Control Centre into a real, secure, auditable platform-operations system (not a dashboard of statistics). Headline requirements:

## 8. BATCH A — ENTITLEMENTS AND PLAN CONTROL
- Feature catalogue: auto-discover and register every real LinkBooks feature (key, name, description, category, module, dependencies, default state, plan availability, limits, metering, cost-to-serve tag, version, rollout, status, change history).
- Permanent Cursor rule: create .cursor/rules/linkbooks-superadmin.mdc (alwaysApply: true, under 60 lines) requiring every new feature or module to register in the catalogue, declare dependencies, entitlement checks, price-book entry (or "included"), metering, audit events and tests, and pointing to docs/superadmin/. Do not weaken existing rules.
- Plan manager: create, edit, duplicate, archive; prices, intervals, currencies, users, companies, transaction/storage/API/usage limits, trials, add-ons, upgrade/downgrade rules, availability. Versioned (draft, review, publish). Existing subscribers are grandfathered unless a migration is explicitly run with notice.
- Per-customer overrides on a business, firm, organisation or subscription: grant, revoke, complimentary, billable add-on, trial, temporary, limit override, effective date, expiry, reason, notes, approval status. Always show each entitlement's source (plan, add-on, grant, trial, override, emergency restriction).
- Resolution order: 1 kill switch/emergency restriction, 2 suspension, 3 explicit revoke, 4 manual grant, 5 add-on, 6 trial, 7 plan, 8 default. Deny beats allow at the same level; the most specific scope wins (user > business > firm > plan); expired items are ignored; every result returns allowed/denied with source and reason. Test exhaustively.
- Dependency graph (required, optional, conflicting, minimum plan, usage and integration dependencies) defined once on the server; warn or block invalid combinations; never hardcode dependencies in frontend modules.
- Rollouts: immediate, scheduled activation and deactivation, percentage rollout, organisation allowlists, internal groups, trial and regional rollouts, global kill switch, rollback to a previous version.
- Safe removal: before confirming, show affected businesses, users and subscriptions, active usage, dependent features, billing impact, data-retention impact and workflow impact. Removal hides or makes data read-only, preserves history and export access, never deletes data. Customer notice (default 14 days unless safety or abuse), read-only grace period, clear locked-state message with upgrade path, email and in-app notification.
- Bulk and high-impact safety: dry-run preview (counts and revenue impact), bulk-size limits, undo window, two-person approval above thresholds, MFA step-up, mandatory reason.
- One central server-side entitlement service used by every module (database policies, edge functions, trusted server code). Frontend only mirrors the result. Changes propagate within seconds via cache invalidation. Consistent locked-feature and upgrade experience.
- Every change writes an audit event (who, what, before and after, reason, when).
- Approvals centre: one inbox for every pending high-risk request (price changes, refunds, bulk entitlement changes, break-glass requests, role changes) with requester, reason, impact summary, expiry, approve or reject by email or mobile, full audit.

### Feature pricing and custom plans (Batch A)
- Price book per feature: any catalogue feature can be sold separately. Models: included in plan, flat fee, per-user, per-unit, tiered, volume, usage-based (included quota plus overage). Each price stores feature, model, amount in integer minor units, currency (USD, GBP, AUD, NZD, INR), interval (monthly or yearly), min/max quantity, tax treatment, effective-from/to, status (draft, live, archived), reason. Prices are versioned; existing subscribers keep their price unless I run a migration with notice.
- Provider sync (test mode): each price change creates a new provider price and archives the old; subscriptions use multiple line items (base plan plus each add-on) with correct proration.
- Customer plan builder: base plan plus add-ons; customer picks a plan, optional features and quantities (users, companies, AI and voice packs) and sees a live itemised quote (monthly and yearly totals, tax per jurisdiction setting, yearly savings). Dependency rules enforced with clear explanations. Self-serve add and remove at any time, effective immediately or next cycle (configurable), proration shown before confirming, removed features become hidden or read-only with data kept. The builder reads the same price book and entitlement service as everything else.
- Admin custom and negotiated plans for one business, firm or group: any feature set, limits, price, fixed term, renewal terms, notes, approval status; per-feature price overrides; percentage or fixed discounts; free periods; complimentary features with expiry. Bundles and packs (e.g. "AI Pack", "Firm Pack") priced below buying items separately. Coupons and promotions with rules (eligible plans or features, duration, usage limits, stacking, expiry); promos are separate objects, never baked into list prices.
- Pricing governance: cost-to-serve model per feature (editable inputs for AI, voice, bank-feed, storage and support costs, using current provider pricing with citations). Flag any price below the configured margin (default 70% gross margin at typical usage, 40% at maximum usage) and block publishing below a price floor unless a second approver confirms. Draft, preview, publish workflow with side-by-side preview of the public pricing page and plan builder; impact analysis before publishing (affected subscribers, revenue and margin change); MFA step-up; two-person approval above thresholds; mandatory reason; full audit; one-click rollback; maximum discount limits per role.
