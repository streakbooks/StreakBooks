# Phase 15 implementation and verification

Date: 31 October 2026. PR: [#48](https://github.com/rohitmehra86/LinkBooks/pull/48).

## User story and boundaries

The user explicitly enrolls and arms a personal wake phrase in Settings → Automation; local PCM capture and acoustic inference activate Signal; browser command recognition feeds predefined rules; typed adapters edit the existing document form; on-screen confirmation invokes its normal draft-save API and renders the result.

| Boundary                    | Evidence                                                                                                                                                                                                                              | Limit                                                                                                                                                        |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Settings → microphone       | No capture on page load or preference enable; real getUserMedia starts after enrollment/Arm. Permission denial is exercised in an isolated Chromium context.                                                                          | Browser permission prompts and physical devices on other OS/browser combinations are not certified.                                                          |
| Microphone → wake detection | AudioWorklet, worker, segmentation, MFCC and DTW run unchanged against spoken WAV capture. Hey LinkBooks, Hello LinkBooks and Hey Luna each enroll and activate. Unrelated speech and the near-sounding Hey Link Cooks stay inactive. | Traditional Flite speech fixtures are a small regression corpus, not a human accuracy benchmark.                                                             |
| Wake → command recognition  | Browser tests verify media tracks have ended before the command recognizer starts. Multiple commands remain active; Stop listening returns to previously armed standby; Stop all releases both stages.                                | Command ASR results are controlled fixtures; no live browser speech-provider reliability or offline command claim.                                           |
| Commands → form state       | Production invoice, quote, sales credit-note and new-bill editors handle focus, dictation, matching, dates, amounts, accounts and tax codes. All 12 Purchases tabs and current sidebar destinations are covered.                      | Other forms retain normal editing; address, FX, advanced tracking and arbitrary controls are not claimed voice-integrated.                                   |
| Form → draft API → UI       | Browser tests inspect real editor mutation payloads and returned navigation, requiring screen confirmation. Tests cover stale confirmations, uncertain saves, linked-credit locks, duplicate callbacks and eligibility.               | Server responses use isolated API fixtures. This is not evidence of live database writes, deployed migrations, RLS integration or production reconciliation. |

## Remaining release evidence

No physical microphone is available in this environment. Independent trials across human speakers, accents, noise, distance, microphones, browsers/OS versions, false activations per hour, missed detections and resource usage remain necessary before a broad wake-feature rollout. The enrolled phrase is personal and speaker/microphone dependent, not authentication. Manual and text controls remain available.

This delivery includes the [15-platform published-capability benchmark and code audit](audit/platform-benchmark-20261031.md), concrete form/navigation fixes, and [engine licensing/privacy/cost review](voice-wake-engine-assessment.md). It does not certify the whole accounting platform as production-ready or implement every advanced feature advertised by those platforms. Financial posting, approvals, payments, deletion and regulatory filing continue through their established manual workflows and server controls.
