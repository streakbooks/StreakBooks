## Processing and controls

1. The account/organisation must have the existing voice feature enabled and the user must have `company.view`. Ordinary server permissions still govern every command.
2. Settings → Automation → Personal wake phrase stores a phrase and preference for the current user, organisation and browser. The assistant panel exposes the same settings. “Hey LinkBooks”, “Hello LinkBooks” and names such as “Hey Luna” require their own enrollment. The label does not verify the words spoken during enrollment: repeat the exact phrase yourself.
3. **Enroll phrase** is an explicit microphone action. Three consistent utterances, separated by silence, produce acoustic feature templates. Enrollment ends after three samples, cancellation, loss of visibility, microphone failure or 30 seconds. Raw PCM is transient, bounded and never written to storage.
4. **Enable wake detection** stores a preference only. **Arm wake detection** explicitly requests the microphone each page/session. Reload, sign-out, organisation/permission changes, disabling, deleting the profile, or a settings change in another tab disarms detection. It never silently starts on page load.
5. The capture requests unprocessed mono audio (browser echo cancellation, noise suppression and automatic gain control off) to keep enrollment and matching acoustically consistent; browsers may still apply device processing. The worklet sends 20 ms mono PCM chunks to a worker. Energy segmentation extracts isolated phrases, resamples to 16 kHz, computes 13 MFCC coefficients using 26 mel bands, and compares variable-length sequences to enrolled examples using band-constrained DTW. A score includes both average and upper-quartile local errors to avoid averaging away a different short phoneme. At least two templates must match the enrollment-calibrated threshold. No STT result is consulted in this stage.
6. A detection releases media tracks, terminates the worker and closes its AudioContext **before** the existing Web Speech command recognizer starts. Signal uses its existing listening animation and stays active through many bounded English commands and navigation.
7. “Stop listening” or Stop assistant stops command recognition, clears pending editing/save state and returns to wake detection **only if already armed and enabled**. Stop wake detection and Stop all microphones release standby capture; the latter stops both stages. Disabling or deleting a profile is immediate. Manual activation remains available.
8. Wake detection pauses in hidden tabs. It does not promise background, locked-screen, cross-application or operating-system wake behavior. Browser/OS permission withdrawal stops capture and requires an explicit retry. Browser command recognition may transmit command audio to its provider and require internet access.

## Privacy and resource boundaries

Templates and the phrase/preference are stored in versioned, validated localStorage keyed to user and organisation, with strict size/shape limits. They are personal voice data, readable by this origin like other browser storage, not an encrypted biometric vault. Delete wake profile removes them; clearing site data also removes them. They are not uploaded, synced, included in financial audit events, or used as authentication. No raw audio recording or conversation history is retained. Audio processing has no network client or API credentials.

## Verification and limits

`npm run test:wake` exercises actual Chromium getUserMedia → AudioWorklet → Worker → VAD → MFCC → DTW → activation. It supplies spoken WAV input through Chromium's media-file capture device; it never stubs the detector or emits a pretend detection. Command speech results and financial server responses are controlled fixtures, so this is not a live browser speech-provider or production database test. Unit tests cover waveform segmentation and positive/distractor acoustic matching as well as lifecycle isolation.

The fixtures use CMU Flite's traditional concatenative `kal` voice, not a generative AI service. They are repeatable signal tests, **not** evidence of human-speaker accuracy. Their generation/provenance is in `e2e/voice/audio/README.md`. No physical microphone is available in the execution environment. Human trials across accents, distance, microphones and room noise, independent negative corpora, false activations per hour, missed detections, and measured CPU/battery behavior remain necessary before a broad rollout. Similar sounds, replayed audio, changed microphones and changed speaking style can cause false activation or misses. Re-enroll or use manual activation.

Browser capability detection requires HTTPS/localhost, getUserMedia, Web Audio, AudioWorklet and Web Workers. Chromium is verified here. Edge, Safari/iOS and Firefox have not been certified by these tests; Web Speech command recognition is also unavailable or restricted in some browsers. Unsupported environments show manual/text alternatives. No claim of universal browser support, guaranteed wake accuracy or full offline command recognition is made.
